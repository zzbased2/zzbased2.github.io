**📌 核心观点：**

- **2025年的本质不是革命，是"涌现"**——多条技术曲线（推理能力、工具稳定性、上下文长度、成本）在同一年交汇到临界点
- RL 的突破不是让模型"学会思考"，而是学会了**采样更多路径并回溯验算**——解锁了推理时间 scaling law
- **Math 和 Code 是 RL 仅有的两种"干净燃料"**，因为它们能提供明确的对错反馈信号
- 真正跑通的杀手应用只有四个：Manus（PPT/报告）、Claude Code（编程）、NotebookLM（知识检索）、OpenClaw（信息流管理）
- Data Agent 的核心瓶颈在**知识工程**（给数据表"写目录"），不在模型能力
- 人与 AI 是"互为假肢"关系——AI 是认知假肢（并行/结构化），人是直觉假肢（长期记忆/方向决策）
- HTML 正在成为万能介质，代码正在变成一种"表达方式"

**✅ 认可的观点：**

- "不是革命，是涌现"的观察非常深刻且克制，避免了大词叙事的陷阱
- "干净燃料"理论解释了为什么 RL 在 Math/Code 上突破而其他领域进展缓慢
- 对 Manus 的评价（"做一百件事不如做对一件事"）切中 Agent 产品的核心问题
- Data Agent 知识工程的分析（代码是文本可检索，数据不是）是非常有价值的第一手经验
- 对 AI 短板的分析（长上下文衰减、缺乏原创直觉、物理世界隔绝）准确而不回避

**⚠️ 需要批判的地方：**

- OpenClaw 的介绍偏理想化，没有深入讨论它在隐私、安全方面的风险（一个 Agent 接管你所有通讯渠道）
- "HTML 取代 PPT"的论断过于乐观——企业环境中 PPT 的协作/审批/分享生态不是 HTML 能轻松替代的
- 文章把"模型工具调用真正 work 的只有命令行和浏览器"说得太绝对，数据库/API 调用在垂直场景已经很成熟
- 对 Vibe Coding 的讨论避重就轻——"debug AI 写的代码比自己写还痛苦"这个问题其实是核心痛点，不能一笔带过

### 005. 历时两个月的GRPO 训练踩坑实录：63% -> 96% tool selection

| 推荐等级 | ⭐⭐⭐⭐⭐                                                                                                |

**📌 核心观点：**

- 用 7B 小模型（Qwen2.5-7B）通过 GRPO 训练，将 tool selection 准确率从 63% 提升到 96%
- **核心突破是 NGRPO**：通过添加虚拟满分样本解决"奖励全部相同 → 零梯度"的关键问题
- **问题定义 > 数据质量 > 算法选择**——这是最核心的经验
- 多个"高级"方法（PRS、GRPO-LEAD、SFT 知识注入）在简单数据集上反而无效
- DART 论文的发现：Reasoning 和 Tool-use 的梯度方向几乎正交，联合训练会互相干扰
- ReAct 格式（thought + action + plan）对多步规划问题至关重要
- 关键监控指标：`frac_reward_zero_std` < 30%、reward 接近 1.0

**✅ 认可的观点：**

- 这是一篇极其高质量的实战复盘，信息密度很高
- "问题定义 > 数据质量 > 算法选择"的排序完全正确，也是很多团队踩坑后的共识
- NGRPO 虚拟满分样本的解法简洁优雅，确实解决了 GRPO 训练中普遍存在的零梯度问题
- 对各种方法的尝试和失败都如实记录，比只写成功案例的文章有价值得多
- ReAct 格式重新定义问题（从单步选择到多步规划）是真正的"顿悟时刻"

**⚠️ 需要批判的地方：**

- 7B 模型在 6 个工具的选择上做到 96% 很好，但这个规模的工具集在实际场景中偏小，扩展到几十上百个工具时结论可能不同
- 奖励函数的设计高度依赖人工经验（如 check_market_status 的 -0.3 惩罚），可扩展性存疑
- 文章没有讨论推理延迟和资源消耗——7B + LoRA 的实际部署成本如何？
- DART 的梯度分离实验只用了简化版，原始论文的完整方案效果可能不同

**📌 核心观点：**

- 这是一篇**极其硬核的技术综述**，系统梳理了 LLM 与电商排序系统结合的三大方向：
  - **LLM→表征**：用 MLLM 替换传统图文编码器，预训练多模态表征加入精排模型
  - **LLM→结构**：借鉴 Transformer/MoE 等结构，探索搜推精排的 Scaling Law
  - **LLM→排序**：Generator-Evaluator 重排框架，本质是强化学习 Actor-Critic 范式
- **核心质疑："新瓶装旧酒？"**——审视后发现很多工作是将已有方法（AutoInt、FFM、RNN重排）穿上 LLM 外衣
- 但作者持开放态度：好的工作不必追求独创，"简单有效地解决问题"同样有意义
- 深刻洞察：**排序模型的天花板不在结构，在样本和特征**——更好的表征/结构只是逼近当前样本的收益上限
- **端到端训练多模态表征 vs 两阶段方案**的权衡分析（训练成本、收敛速度差异、噪声点击）
- 对比学习的全面梳理：正例构造、负例选择、损失函数（InfoNCE/Triplet/Circle Loss）

**✅ 认可的观点：**

- **数据循环陷阱的深层洞察**："更强的表征可能加剧打压新趋势曝光"这个反直觉观点，是全文最有穿透力的分析
- "新瓶装旧酒"的质疑角度非常有价值——在 AI 概念泛滥的时代，保持冷静审视很难得
- 对表征训练中"电商语料 vs 自然语料"分布差异的分析精准，这是很多做通用多模态的人容易忽略的
- "ID 与图文、语义与协同不是对立关系"的观点成熟且实用
- Sparse MoE 在搜推场景的应用分析（路由网络、共享专家、私有专家）非常细致
- GE 重排框架的推导清晰，从规则→保守派→改良派→激进派的递进逻辑优秀
- 参考文献列表完整（40+ 篇），学术严谨性高

**⚠️ 需要批判的地方：**

- 文章篇幅极长（约 2 万字），信息密度虽高但阅读门槛也高，缺少图表辅助（可能被爬虫丢失）
- 对 OneRec 等"召排一体"方案只是提及但未深入评价，这恰恰是最前沿也最有争议的方向
- "公司有人有钱愿意投入资源挺好的，作为员工也有新事情可以干"——这种观点虽然现实但可能助长了"为论文而论文"的风气
- 缺少实验数据支撑——文章定位是综述/观点，但如果能加入实际业务数据对比会更有说服力

**核心观点：**

- 2025 双 11 中，生成式大模型范式贡献了 60% 的算法提效——标志着搜广推进入生成式时代
- 两大核心突破：(1) Next Item Prediction 作为学习范式（LUM），MFU 超 40%；(2) 自研 FAT 模型（Projection 层按特征域扩展参数），1B 参数下 MFU 达 20%
- FAT 的本质创新：LLM 的 token 同质（语言符号），但搜广推的 token 异构（用户行为/商品属性/上下文）——因此在 Projection 层而非 FFN 层扩展参数
- 生成式召回：GFlowGR（生成流框架） + NEZHA（10ms 实时推理） + VALUE（带权 Trie 树约束改写）
- 累计成果：召回营收 +8%，精排 CTR +13%，相关性 goodrate +27%，多模态 CTR +20%

**认可的观点：**

- "搜广推的 token 异构性"这个洞察是全文最有价值的点
- GFlowGR 用生成流框架建模召回，理论优雅且实验结果强劲
- 全链路数据透明：营收/CTR/goodrate 的累计提升数字可信度高

**需要批判的地方：**

- 全文是阿里妈妈官方宣传文，只报正面数据
- FAT 离充分验证 Scaling Law 还有距离
- 缺少与竞品的横向对比

### 077. OneRec: 希望更多的人来研究端到端推荐

| 属性   | 信息                                                                                                   |
| ---- | ---------------------------------------------------------------------------------------------------- |
| 操作   | 👍 赞同了文章                                                                                             |
| 时间   | 2025-06-19 08:39                                                                                     |
| 类型   | article                                                                                              |
| 链接   | [https://zhuanlan.zhihu.com/p/1918350919508140128](https://zhuanlan.zhihu.com/p/1918350919508140128) |
| 推荐等级 | ⭐⭐⭐⭐⭐                                                                                                |

**核心观点：**

- 端到端推荐系统是推荐领域的下一个范式跃迁——用一个模型取代召回/粗排/精排/重排的级联架构
- 推荐系统当前遇到明显的 Scaling 瓶颈：行为序列长度和打分候选集两个维度都已到天花板，MFU低至个位数
- 经济账算得过来：10B 模型 + 1K Token/样本，在 L20 卡上服务，单卡日广告收入约 516 元 vs 成本 84 元，毛利可达 84%
- 推荐模型没有 Scaling Law 的三个根因：判别式问题定义限制智力天花板；Code Book 太大（1B item ID vs LLM 的 100K token）缺乏 ngram 共现；无法做深度检索
- OneRec 方案：将推荐重新定义为生成任务，缩小 Code Book，MFU 做到 20-30%；线上 1B MoE 模型，全目标 Beat 非端到端系统，成本仅为 base 系统的 1/10
- 未来三大方向：Reward System 设计、更 solid 的 Scaling Law（V2 即将发布）、推荐行为模态与 LLM 多模态对齐

**认可的观点：**

- 极其难得的工业级深度技术反思，从经济学、信息论、系统工程三个维度论证端到端推荐的必要性
- 非端到端系统的算力效率会持续恶化的洞察极其精准
- Code Book 分析（1B item ID 无 ngram 共现 vs 100K token 有大量 ngram）是全文最有原创性的洞察
- 经济账的推导思路——先算账再做技术——值得学习
- RL 在端到端系统中才能真正发挥作用的论断非常有远见

**需要批判的地方：**

- 对端到端优势描述偏理想化——从级联架构迁移的组织阻力和工程成本被低估
- 判别式模型智力天花板有限的论证主要基于直觉和假设，缺乏严格证明
- 1B MoE 全目标 Beat 没有给出具体数据
- 对端到端方案的局限性（冷启动、可解释性、多业务目标精细调控）讨论不足

**核心观点：**

- Bad Case 是推荐/搜索系统精细化运营的核心抓手——"细节决定成败"
- Bad Case 四分类：功能性 Bug（致命）、体验性问题（重点）、政治正确性问题（致命）、不明确问题（需数据分析）
- 分析方法论：先用数据量化（覆盖率/严重性），再排优先级；"不要先说对错，请先用数据分析度量"
- 处理策略：快速版（规则干预）-> 复杂版（融入模型：特征/样本/模型三个维度）-> 定期规则收口
- 核心闭环：Bad Case 收集 -> 数据分析 -> 策略尝试 -> 线上指标观测 -> 新一轮发现
- 实用技巧：高流低转商品提取器、长短期指标关联分析、预览平台抽样评估、反向 AB 实验验证长期效果

**认可的观点：**

- 这是一篇极高实战价值的文章——几乎每个案例都可以直接复用到工作中
- "无法衡量就无法优化"的原则贯穿全文，体现了数据驱动的工程素养
- 三个线上 Case 分析（实时性/类目分布/多样性）的数据拆解过程堪称教科书级别
- "做了不一定能提升长期留存，但不做肯定会让长期留存变低"的判断标准非常务实
- 离线 Case 中 NN vs GBDT 的错分样本对比分析方法论极其实用
- "通过监控做到早于老板发现问题"——这是算法工程师的终极目标

**需要批判的地方：**

- 文章写于 2020 年左右，部分技术细节已过时（如 GBDT vs NN 的对比在深度学习主导的今天已不太常见）
- 篇幅过长（1 万字+），部分案例可以更精炼
- 缺少对 LLM 时代 Bad Case 的讨论——如幻觉、安全性、对齐失败等新型 Bad Case
- "知识星球"推广内容占了不少篇幅，影响阅读体验

- 仅模拟精排做粗排短期有收益，长期会加剧马太效应，使曝光集中度越来越高
- 提出**ASH@K（All-Scenario Hitrate）**指标替代AUC评估粗排——跨场景关联成交样本构建更全面的评估
- **SSB问题的解决**：训练样本需包含曝光样本+精排候选（困难负样本）+粗排候选（简单负样本），三者缺一不可
- **标签创新**：全场景购买标签（ASPL）、全场景点击标签（ASCL）、自适应曝光标签（AEL）三层递进

- 蒸馏只在曝光样本上有效——精排模型在RC和PRC样本上不是好老师

**✅ 认可的观点：**

- **"粗排目标是无序集合而非有序列表"是本文最核心的贡献**——这一视角转变足以改变整个粗排的研究方向
- ASH@K指标的设计思路（跨场景关联正样本）非常巧妙——解决了单场景hitrate的局限性
- "AUC与在线业务指标不一致"的根因分析（帕累托前沿的跷跷板效应）逻辑严密
- 粗排超精排的实验结果极具说服力——直接证明了"粗排≠小精排"
- 三类样本+三类标签的设计体系完整，工业落地路径清晰

- ASH@K中跨场景query构造方法（选相关性超阈值的最近query）比较粗糙——可能引入大量噪声

### 103. 深度学习的多个loss如何平衡？

| 属性   | 信息                                                                                                                       |

| 操作   | 👍 赞同了回答                                                                                                                 |

| 链接   | [https://www.zhihu.com/question/375794498/answer/2307552166](https://www.zhihu.com/question/375794498/answer/2307552166) |
| 推荐等级 | ⭐⭐⭐                                                                                                                      |

**📌 核心观点：**

- **Pareto优化理论**是多loss平衡的理论最优解——Multi-Task Learning as Multi-Objective Optimization（NeurIPS 2018）
- **实用经验**：loss尺度一般不太影响性能，除非辅助loss权重太大喧宾夺主
- **hzwer的玄学躺平做法**：`loss = loss1/loss1.detach() + loss2/loss2.detach()` —— 每个iteration自动对齐多loss尺度
- 更科学的版本：`loss = loss1 + loss2/(loss2/loss1).detach()` —— 以loss1为锚点对齐
- **Bayesian框架**：根据各loss分量当前大小自动设定权重（Kendall等人 CVPR2018）
- 核心洞察："loss就像菲涅尔透镜，纵使你能设计它的含义，也很难设计它的梯度"
- "很多paper设计一堆loss只是为了让核心故事更完整，未必强过调参"

**✅ 认可的观点：**

- Pareto优化是目前最有理论根基的方案，"套进任何方法里基本都会涨点"的实测结论非常有价值
- hzwer的detach对齐技巧简洁优雅，实际工程中极其实用——几乎零成本就能解决多loss尺度问题
- "loss含义可设计但梯度难设计"这一洞察深刻——多数人只关注loss的物理意义而忽略了梯度行为
- "很多paper的多loss只是凑故事"——一针见血，在推荐系统领域尤为常见

**⚠️ 需要批判的地方：**

- 这是一个知乎问答的汇总，多个答主的回答拼在一起，缺乏系统性
- Pareto优化在大规模工业场景（如推荐系统多目标优化）的计算开销没有讨论
- detach技巧虽然实用但缺乏理论分析——在什么条件下会失效？
- 完全没有提到GradNorm、PCGrad等更现代的梯度级多任务优化方法
- 缺少对"何时应该用多loss vs 何时应该简化为单loss"这个更根本问题的讨论

| 推荐等级 | ⭐⭐⭐                                                                                                                      |

**核心观点：**

- 双塔召回需要ANN检索，但点积不满足三角不等式（非度量空间），HNSW在点乘距离上效果差
- L2归一化将双塔点积行为转化为欧式距离，保证了训练和检索的一致性
- Temperature的作用是放大logit——归一化后点积值域在[-1,1]，导致正样本loss仍然很大，temperature放大logit让模型更容易学习
- Temperature的trade-off：大倍数时boundary（难样本）学得好但centroid几乎无梯度；小倍数时centroid学得好
- Heated-up方法：先大倍数学难样本，再小倍数fine-tune把决策面学好
- 归一化约束向量仅通过夹角表示距离，可降低热度效应；再加item_bias学习热度并在serving时提权突出个性化

**认可的观点：**

- 从ANN检索一致性角度解释L2 Norm是最本质的解释——点积不保序的反例（A=(100,0),B=(0,100),C=(101,0)）简洁有力
- Temperature的centroid vs boundary trade-off分析直观易懂
- Heated-up方法（先难后易）符合课程学习的直觉
- "归一化+temperature+item_bias"的三件套组合是工业界的标准做法，总结到位

**需要批判的地方：**

- 篇幅较短（1230字），对温度系数的具体选择策略没有给出实践建议（具体该设多少？）
- Heated-up方法在工业界的实际落地效果没有数据支撑
- 没有讨论L2 Norm对模型表达能力的限制——归一化后向量模长信息丢失，某些场景下这个信息是有用的

**📌 核心观点：**

- LLM是无状态函数，长窗口≠长期记忆——10M Token的Context Window不能替代Memory模块

- Memory方向三个重点子领域：记忆的结构化与压缩（对话→知识图谱）、检索逻辑升级（超越纯向量相似度）、遗忘机制（主动遗忘过时/冲突信息）
- 检索评分黄金法则：Retrieval Score = Recency × α + Importance × β + Relevance × γ（源自Stanford Generative Agents）
- Memory应该是外挂的（Non-parametric），不应通过SFT灌入模型参数——因为知识会过时
- 多智能体共享记忆（Hive Mind）是工业界关注的蓝海方向

**✅ 认可的观点：**

- 对长窗口vs记忆的辨析非常到位——"10M Token是你的一次输入能力，不是你的长期记忆"，这个区分很多人没想清楚
- "苹果→戒糖"的例子非常直观地说明了状态冲突问题，这确实是当前RAG系统的核心痛点
- 三个研究子方向的建议都很实用：结构化记忆（KG）、检索逻辑、遗忘机制，每个都有明确的论文切入点
- "Memorization is Compression"的概括精准——信息压缩质量决定了Memory系统的上限
- 建议从源码入手（LangChain/Mem0/Zep）而非只读论文，体现了工程导向的务实态度

**⚠️ 需要批判的地方：**

- 文章面向研0学生写，行文偏鸡汤化，"干就完了"等口号过多，信息密度被稀释
- 对Mem0和Zep的推荐缺乏具体的技术对比——两者的架构差异、适用场景、局限性都没有展开

- Mixed parameterization的设计分析到位——S-tokens共享参数减少计算，NS-tokens独立参数保留语义差异
- 最后"完结撒花，希望我能早日找到工作"的签名很真实，说明作者是一个在求职中的同学的真诚分享

| 链接  | [https://www.zhihu.com/question/7767333624/answer/1987308164878706256](https://www.zhihu.com/question/7767333624/answer/1987308164878706256) |

**📌 核心观点：**

- LLM-as-Judge 和 Reward Model 各有优势，核心是三个 trade-off：
  1. **算力/时延**：RL训练中每次生成Response都需要打分（百万到千万次），70B的LLM-as-Judge太重，RM（7B甚至BERT-like）只需一次Forward Pass输出标量，速度极快
  2. **判别式vs生成式**：RM通过Pairwise Ranking Loss训练，输出连续实数值，梯度信号密集平滑；LLM-as-Judge易受Position Bias和Verbosity Bias影响
  3. **OOD鲁棒性**：RM在训练分布外容易被Reward Hacking，LLM-as-Judge因为见多识广反而更鲁棒
- 业界最佳实践：RLAIF——**用LLM-as-Judge生产数据，蒸馏给轻量RM，用RM跑PPO，定期用LLM检查RM质量**

**✅ 认可的观点：**

- **三个trade-off的框架非常清晰**——把一个复杂问题拆解成算力、信号质量、泛化性三个正交维度
- RLAIF的迭代流程描述准确——LLM标注数据→训练RM→跑PPO→发现Reward Hacking→补数据重训，这是工业界标准做法
- 对RM输出连续标量vs LLM输出离散评分的对比切中要害——梯度友好度确实是RL内循环的核心需求
- 文章简洁精炼（1500字），没有废话，每段都有实质性信息

**⚠️ 需要批判的地方：**

- 篇幅过短，对每个trade-off的展开不够深入——比如RM的Reward Hacking具体有哪些形式？如何检测？
- 没有提到 Process Reward Model（PRM）vs Outcome Reward Model（ORM）——这是2025年RL训练的热门话题
- 对Constitutional AI、RLHF without RM（直接用LLM做RL）等更新的范式未提及
- "用BERT-like模型做RM"的说法在2025年已经偏保守——现在主流RM都是基于LLM backbone的
- 缺少对具体场景的建议——什么时候该用哪种方案？不同规模团队的最佳实践是什么？

4. **Scaling Up后手工交叉特征反而有害**：随着Transformer层数和宽度增加，那些曾经带来大增益的FM/笛卡尔积特征反而伤害泛化性，说明Transformer自身的交叉能力在足够规模下可以替代人工特征工程。

**认可的观点：**

3. **语义ID在判别式模型中的4种特征用法很实用**：ID-based、List-wise、Cross、Dense四种特征构造方式非常具体，直接可落地。尤其是Cross ID-based特征（基于SID前缀匹配计数），是一种简单但有效的利用语义ID层次结构的方法。
4. **线上效果显著**：eCPM+3.48%，冷启动场景+8.98%，这在广告系统中是非常显著的提升。

**需要批判的地方：**
1. **Loss函数过于复杂**：作者自己也感叹"Loss是真的多"。U2I对齐×2 + U2U/I2I对齐×2 + 共现对齐×2 + CF有偏/无偏Loss + 纠偏约束Loss + RQ-VAE Loss，如此多的Loss叠加在一起，每个Loss的权重如何调节？各Loss之间是否存在冲突？这些问题文中缺乏深入讨论。
2. **端到端训练的稳定性存疑**：同时训练RQ-VAE量化、CF模型纠偏、多视角对齐三个模块，训练的稳定性和收敛性如何保证？论文未充分讨论训练技巧和潜在的坍塌风险。
3. **User侧SID的必要性不够清晰**：传统上语义ID主要用于Item侧，DAS同时对User做SID提取的动机和独特价值，文中论述不够充分。从消融实验看，User侧SID的边际收益需要更清晰的量化。
4. **对比实验缺乏与QARM、OneRec等同类方案的直接对比**：文中提到了这些方案属于"两阶段对齐"范式，但实验部分没有将它们作为baseline进行对比。

> **推荐等级：⭐⭐⭐⭐** 语义ID对齐是当前生成式推荐的核心问题之一，DAS的端到端方案和因果纠偏思路都有新意。适合关注语义ID和生成式推荐方向的从业者阅读。

- 数据使用扎实，7条预测全部用真实贸易数据验证，说服力强

- 线上线下特征不一致的分析极其细致——特别是"4月16日0-4点使用4月14日特征"的例子，把pipeline延迟导致的不一致讲得非常具体
- "两个team优化同一场景，一个team提升后另一个team什么都不做也会涨"——这个观察非常精彩，深刻揭示了推荐系统的数据飞轮效应
- 解决方案务实：特征落地保证一致性、无偏数据上采样、新旧模型线性融合逐步过渡

**需要批判的地方：**
- 文章只聚焦了"离线涨线上跌"这一个坑，标题说的"什么坑"（复数）其实只详细展开了一个
- 对数据穿越的分析过于简略——"一般相对好查"一笔带过，但实际中特征穿越往往非常隐蔽
- 模型融合的方法 pctr=a*pctr_new+(1-a)*pctr_old 虽然work但缺乏理论依据，a的调节策略也没有展开
- 缺少对Position Bias、Selection Bias等更深层偏差问题的讨论

> **推荐等级：⭐⭐⭐⭐⭐** 这是推荐系统从业者必读的实战经验分享。"冰山效应"的分析和"两个team互相受益"的观察都极具洞察力，对理解推荐系统的数据偏差问题有重要价值。
